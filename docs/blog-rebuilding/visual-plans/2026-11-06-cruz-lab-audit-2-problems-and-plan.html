Cruz Lab · 구조 전수조사 2/2

글을 못 쓰게 만드는 건 편집기보다 초안이 브라우저에만 있는 구조다

2026-05-05 이후 새 글이 없다. 원인은 쓰기 마찰이다. 초안은 기기에 묶이고, 비공개 글은 사라지고, 출간은 외부 서비스 4곳을 직렬로 지난다. 그 위에 보안 구멍 2개와 소스 모드 편집기가 있다. 비용이 들어도 구조를 고친다.

전제: 1편(현재 상태) · 기준일 2026-11-06 · 타협안 없음 · 2차 개정: 10절(시리즈 평가 · 사이트 방향 · docs 관리) 추가

결론

일곱 가지 판단

  1. 최우선 과제는 쓰기 마찰이다. 초안 서버화, 비공개 글 관리, 출간 경로 단순화가 편집기 교체보다 먼저다.
  2. 보안 구멍 2개는 즉시 막는다. 규칙에서 클라이언트 쓰기를 전면 금지하고, 비공개 글 API에 인증을 붙인다.
  3. 저장소를 원본 1곳 + 비동기 백업 1곳으로 줄인다. content/posts 57개와 빈 Cloud Function, 쓰지 않는 업로드 API를 지운다.
  4. 편집기는 수정이 아니라 교체다. 소스 모드 CodeMirror에는 명령·단축키·플러그인을 등록할 구조가 없다. Tiptap으로 간다.
  5. Astro + React 구조는 맞다. 배치가 틀렸다. 공개 페이지에서 React 장식을 빼고, 관리자·에디터에 React를 집중한다.
  6. UI는 2021~2023년 포트폴리오 문법이다. 사이트의 방향은 "블로그가 본체, 포트폴리오는 /about + /projects + PDF"로 정한다(10.2). 글 상세에 목차·연재·이전다음·코드 복사를 넣는다.
  7. 시리즈는 독립 기능으로는 과투자다. 시리즈 2개 = 태그 2개와 같은 집합, 코드 2,514줄(16%). 글의 필드 series:{key,order}로 축소하고, 분류의 주축은 category(접두사 승격) + tags로(10.1).
  8. 동작하지 않는 기능 4개를 고친다. 시리즈 수정, 시리즈 진행률, 비공개 글, 이미지 정리.

8 · 개선안

Firebase는 유지하고, 컬렉션 구조·규칙·경로를 다시 짠다

posts/{id}
  slug · title · description · tags[] · seriesId? · seriesOrder? · kind: post | note | project
  status: draft | published | unlisted | scheduled · publishedAt? · scheduledAt? · updatedAt · createdAt
  cover: { kind: generated | image, assetId? }
  published: { markdown, readingTime, wordCount, toc[] }     ← 공개 페이지가 읽는 스냅샷
  draft:     { markdown, editorJson, updatedAt, device }     ← 서버 초안
posts/{id}/revisions/{rev}      ← 발행할 때마다 published 복사
series/{id}                     ← name · slug · description · coverAssetId · order · status
assets/{id}                     ← storagePath · variants{w480,w960,w1600 webp} · width · height · bytes · usedBy[] · uploadedAt
settings/editor                 ← keymap · 슬래시 순서 · 기본 보기 모드
publishLog/{id}                 ← postId · action · at · by

왜 Firestore를 유지하나. 관계형 DB로 옮겨 얻는 것(전문 검색, 조인)보다 이전 비용이 크다. 수백 편 이하면 검색은 클라이언트 인덱스(Pagefind 또는 JSON + MiniSearch)로 충분하다. 바꿔야 할 것은 DB가 아니라 컬렉션 구조와 규칙과 경로다.

하지 않을 것. Next.js 등 프레임워크 교체(4절). Firestore → Postgres 이전(위). CodeMirror 라이브 프리뷰 자체 구현(2절). 기존 글 URL 변경(/blog/<slug> 유지).

9 · 검증

개선 후 이것이 참이어야 한다

보안

관리자가 아닌 Google 계정의 클라이언트 SDK 쓰기 → 거부. by-slug?slug=<비공개> → 401/404.

쓰기 마찰

폰에서 노트 작성 → 데스크톱에서 같은 초안 열림 → 발행 → 60초 안 공개 반영. 시간 측정.

왕복

기존 56편을 새 에디터로 열고 수정 없이 저장 → diff 0.

공개 페이지

JS 비활성화로 홈·목록·상세 전부 읽힘. /blog/ HTML ≤ 100 KB. Lighthouse 모바일 ≥ 90.

관리자

비공개 글이 목록에 보이고 미리보기가 열림. 시리즈 수정이 열림. 글 삭제 시 이미지도 삭제.

이유

이유

이유
