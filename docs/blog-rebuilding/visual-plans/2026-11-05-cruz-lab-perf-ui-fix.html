① GNB 라우팅

Projects만 빨랐던 이유: 혼자 CDN에 저장된 정적 페이지였다

/projects/는 prerender = true입니다. 빌드할 때 HTML을 만들어 CDN에 둡니다. Home, Blog, Series는 SSR입니다. 요청마다 서버리스 함수가 Firestore를 읽고 HTML을 만듭니다. 캐시 헤더가 없어 응답은 x-vercel-cache: MISS였습니다. ClientRouter는 다음 페이지 HTML을 끝까지 받은 뒤 화면을 바꿉니다. 그래서 클릭 후 1초 넘게 아무 일도 없어 보였습니다.

수정 전 코드

// 전: 공개 페이지가 매 요청마다 Firestore 전체 글 목록을 다시 읽는다
// - CDN 캐시 헤더가 없다 → Vercel 응답: cache-control: public, max-age=0, must-revalidate
// - x-vercel-cache: MISS (매번 서버리스 함수 실행)
export async function listPublishedFirestorePosts() {
  const snapshot = await db.collection('posts').orderBy('pubDate', 'desc').get();
  return snapshot.docs.filter(isPublished).map(buildContentPost);
}

// 후 ②: 서버 메모리 캐시 + 동시 요청 합치기 (src/lib/server/memo-cache.ts)
export function memoize<T>(key: string, loader: () => Promise<T>, ttlMs = 60_000) {
  const hit = store.get(key);
  if (hit && hit.expiresAt > Date.now()) return hit.promise;   // 진행 중인 Promise도 공유
  const promise = loader().catch((e) => { store.delete(key); throw e; });
  store.set(key, { expiresAt: Date.now() + ttlMs, promise });
  return promise;
}

export async function listPublishedFirestorePosts() {
  return memoize('posts:list', async () => { /* 기존 조회 그대로 */ });
}

CDN 캐시 효과는 배포 후에만 확인할 수 있습니다. 로컬에서는 헤더가 붙는 것과 메모리 캐시 효과를 확인했습니다. 404 응답에는 캐시 헤더를 붙이지 않습니다. 관리자 페이지와 관리자 API도 제외했습니다.

export async function getPublishedSeriesWithReadingTime() {

④ 프로필 틸트

회전 방향은 맞았다. 원근이 없어 왼쪽 아래와 오른쪽 위가 같은 모양으로 보였다

네 모서리에 마우스를 올리고 화면에 그려진 네 꼭짓점 좌표를 쟀습니다. 회전 부호는 수정 전에도 맞았습니다. 마우스가 있는 모서리의 z가 가장 작았습니다(약 −60 px, 화면 안쪽). 그러나 부모에 perspective가 없었습니다. 원근 없이 납작하게 투영하면 (rotateX, rotateY)와 (−rotateX, −rotateY)가 같은 모양이 됩니다. 그래서 아래쪽 동작이 위쪽과 반대로 보였습니다.

두 번째 문제도 있었습니다. 기운 요소 자신의 getBoundingClientRect()로 마우스 위치를 쟀습니다. 기울수록 사각형이 바뀌어 값이 흔들렸습니다. 이제 기울지 않는 바깥 래퍼에서 잽니다. 광택, 반대쪽 그림자, 앞뒤 층 깊이(translateZ), 3.5% 확대를 더했습니다. 블로그 카드의 TiltCard도 같은 버그가 있어 같은 방식으로 고쳤습니다.

수정 전
// 전: 기우는 요소 자신에 이벤트를 걸고, 그 요소의 사각형으로 위치를 잰다
//     부모에 perspective가 없다 → 원근 없이 납작하게 회전 (정사영)
<motion.div
  onMouseMove={handleMouseMove}               // e.currentTarget = 기운 요소
  style={{ rotateX, rotateY, transformStyle: 'preserve-3d' }}
>
const rect = e.currentTarget.getBoundingClientRect();  // 기울수록 사각형이 바뀐다
수정 후
// 후: 바깥 div는 기울지 않는다. perspective를 주고 포인터 위치를 잰다
<div
  style={{ perspective: '900px' }}
  onPointerEnter={handlePointerEnter}
  onPointerMove={handlePointerMove}           // e.currentTarget = 고정된 래퍼
  onPointerLeave={handlePointerLeave}

      <img ... />
      <motion.div style={{ background: glare, opacity: glareOpacity }} />  {/* 광택 */}
    </motion.div>
  </motion.div>
</div>

⑤ 블로그 썸네일

단색 배경 + 텍스트 이미지를 코드가 그리는 커버로 바꿨다

예전 썸네일은 글마다 업로드한 이미지였습니다. 단색 배경에 제목과 이모지를 얹은 형태라 제목이 카드 안에서 두 번 나왔습니다. 새 커버는 이미지를 쓰지 않습니다. 메시 그라디언트, 필름 노이즈, 기울어진 격자, 큰 카테고리 글자로 그립니다. 같은 카테고리는 같은 색 계열입니다. 블롭 배치는 slug로 정해 글마다 다릅니다. 호버하면 그라디언트 층만 transform으로 움직입니다.

// src/lib/post-cover.ts — 카테고리로 색 계열, slug로 블롭 배치를 정한다 (같은 입력 → 같은 결과)
export function getCoverLabel(title: string, tags: string[]) {
  const bracket = title.match(/^\s*\[([^\]]+)\]/);   // "[Pintos] Threads ..." → "Pintos"
  if (bracket) return bracket[1].trim();
  return tags[0] ?? 'Note';
}

검증 범위와 남은 일

로컬에서 측정해 확인했다. CDN 캐시 효과는 배포 후 다시 재야 한다

확인함
  • 로컬 프로덕션 빌드에서 수정 전·후 A/B 측정
  • 틸트 네 모서리 좌표·스크린샷

  • 시리즈 읽기 시간 결과 동일

  • 타입 오류 65 → 27개 (새 오류 없음)
배포 후 확인
  • 프로덕션 x-vercel-cache: HIT와 GNB 이동 시간
  • 글 수정 뒤 최대 60초(+1요청) 동안 이전 내용이 보일 수 있음. 같은 인스턴스는 바로 반영

  • src/lib/series.ts가 서버에서 클라이언트 Firebase SDK를 씁니다. Admin SDK로 바꾸면 콜드 시간이 줄 수 있습니다.
