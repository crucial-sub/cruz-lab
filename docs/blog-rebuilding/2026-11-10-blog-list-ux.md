# 재건 4단계 보강: `/blog` 글 목록 표시 방식 UX 분석

- 날짜: 2026-11-10
- 대상: `/blog`, `/blog/category/<key>`, `/blog/tag/<tag>`의 글 목록(`BlogList.astro`)
- 관계 문서: [4단계 Plan](./2026-11-09-stage4-public-site-plan.md) D9·D17·13절·15절, [4단계 작업 문서](./2026-11-09-stage4-public-site.md) 2.4·5절 33·34·39, [감사 문서](./2026-11-06-blog-architecture-audit-2-problems-and-plan.md) 6.1 U9·U10·U14
- 시각 문서: [visual-plans/2026-11-10-cruz-lab-blog-list-ux.html](./visual-plans/2026-11-10-cruz-lab-blog-list-ux.html) (실제 글 54편 데이터로 그린 목업. 1280px·390px)
- 상태: 결정 완료(8절·11절). Plan 13절 D19와 15절에 적었다(2026-11-10). 구현은 브랜치 `stage4/d-blog-list`.

## 0. 결론 먼저

1. 친구의 피드백은 "리스트라서 나쁘다"가 아니다. **항목당 정보가 적고, 54개 항목이 모두 같은 모양이라 초점이 없다**는 뜻이다.
2. 옛 그리드가 좋아 보인 이유는 썸네일 그 자체가 아니다. 카드마다 **색(코드 커버) · 큰 제목 · 설명 2줄 · 카드 사이 여백**이 있었기 때문이다. 참고 사이트 6곳 중 4곳은 썸네일 없이 같은 효과를 낸다.
3. 대안은 3개다. **A 그리드 기본 + 목록 토글**, **B 매거진형(대표 1편 + 썸네일 행)**, **C 목록 강화(커버 없음)**. 권장은 A다. 친구(첫 방문자)가 원한 모양이고, 홈의 카드와 같은 컴포넌트를 쓰며, 지금 목록은 토글로 남는다.
4. 어느 대안이든 함께 할 것: 모바일은 커버 작은 가로 카드, 설명은 2줄 이상, 카테고리 9개가 서로 다른 색을 갖게 팔레트 배정을 고친다(지금은 9개 중 5개가 같은 색).
5. 이것은 승인된 Plan의 U10·D17을 뒤집는 일이다. 사용자 결정(D19)으로 기록한다.
6. **결정(2026-11-10): B 매거진형, 토글 없음, 모바일도 매거진형, 대표 글은 최신 글 1편 자동**(8절). 친구가 비교 HTML을 보고 골랐다. 추가 피드백(필터 영역이 지저분하다)은 11절에서 분석한다.

## 1. 문제 제기

사용자의 친구가 localhost의 새 `/blog`를 보고 말했다(2026-11-10):

- 리스트 방식이 너무 딱딱하다.
- 한눈에 들어오지 않아 뭘 읽어야 할지 바로 감이 안 온다.
- "어, 이 글 재밌어 보인다. 읽어봐야지" 하는 포인트가 있어야 한다.
- 이전의 썸네일이 보이던 그리드 형식이 더 좋아 보인다.

사용자의 요청: UI/UX 관점에서 분석한다. 지금 방식은 없애지 않는다. 그리드(또는 그 포인트를 더 잘 살리는 방식)와 토글로 오가도 좋다.

### 2.3 진단

지금 목록은 **"찾기"에 맞춘 화면**이다. 제목을 아는 사람, 태그로 좁히는 사람, 검색어가 있는 사람에게 빠르다(작성자 자신, 재방문자). 그러나 **"둘러보기"에는 약하다**. 처음 온 사람은 제목만 보고 고른다. 그 사람이 받는 정보는 1280px에서 제목 + 설명 1줄(1/4은 잘림), 390px에서 제목뿐이다.

문제를 셋으로 나눈다.

1. **항목당 정보량이 적다.** 설명 1줄(모바일 0줄). 연재 글 21편은 제목이 번호와 영문 몇 단어다.
2. **차별화가 없다.** 54행이 같은 크기·무게·색이다. 날짜와 연도 머리는 모두 같은 달이라 구분 기능을 잃었다. 눈이 멈출 자리가 없다.
3. **시각 앵커가 없다.** 색·모양 변화가 0이다. 옛 그리드는 카드마다 색 블록이 있었고, 그것이 친구가 기억한 "썸네일"이다. 이 사이트의 커버는 코드로 그린다(U14). 사진을 고르는 비용이 없다.

## 3. 친구의 말을 UX 원리로 풀기

| 친구의 말 | 원리 | 지금 화면 | 해법의 방향 |
|---|---|---|---|
| "딱딱하다" | 시각 리듬. 같은 요소가 반복되면 표(table)로 읽힌다. 눈은 변화가 있는 곳에서 멈춘다 | 76px 행 54개, 글자만, 1색 | 항목 사이 여백, 색 블록 또는 크기 차이 |
| "뭘 읽어야 할지 감이 안 온다" | 정보 냄새(information scent). 링크가 그 글이 줄 것을 얼마나 예고하는가 | 제목 + 설명 1줄(잘림). 모바일은 제목만 | 설명 2줄 이상을 늘 보인다. 큰 제목 |
| "재밌어 보이는 포인트" | 발견(discovery) 모드. 목표 없이 훑는 독자는 **약속**(설명 문장)과 **정체성**(색·카테고리)으로 고른다 | 둘 다 약함 | 카테고리 색, 설명 전부, 대표 글(선택) |
| "썸네일 그리드가 낫다" | 썸네일은 시각 앵커의 한 형태다. 참고 사이트 6곳 중 4곳은 썸네일 없이 큰 제목 + 설명 2~4줄 + 여백으로 같은 효과를 낸다 | 커버 컴포넌트가 이미 있다(홈·OG) | 코드 커버를 목록에도 쓴다(A·B) 또는 글자만으로 만든다(C) |

**탐색(navigation)과 발견(discovery)의 균형.** 이 블로그의 목적(취업 준비, 포트폴리오)상 첫 방문자(채용 담당자, 동료)가 재방문자보다 많다. 첫 방문자는 발견 모드다. 그래서 기본 표시는 발견에 맞추고, 찾기는 탭·칩·검색(그리고 토글)이 맡는 것이 맞다.

공통점:

1. 설명이 2~4줄 **전부** 보인다. 1줄 말줄임은 없다.
2. 제목이 크다(18~28px). 지금 16px.
3. 항목 사이 여백이 커서 한 항목씩 읽힌다.
4. 썸네일은 디자이너가 있는 조직(kakao)이나 플랫폼(velog)이 쓴다. 개인·엔지니어링 블로그(toss, josh, vercel, 우아한)는 글자와 여백으로 만든다.
5. 상단에 "인기"·"추천"·히어로로 **한두 편을 띄운다**(toss, josh, 우아한).

## 5. 대안

세 대안 모두 공통으로 지킨다: `<li data-post-row>` 유지(검색 필터·스모크), 제목 링크 하나 + 가상 요소(5절 33), JS 없이 기본 표시 완전, React 0, `/blog` HTML 100 KB 이하, 카테고리 탭·태그 칩·검색은 그대로.

### 5.1 A. 그리드 기본 + 목록 토글 (권장)

- **데스크톱(≥ 640px):** 홈의 `PostCard`(코드 커버 16:9 → 카테고리 · 날짜 → 제목 19px/700 → 설명 2~3줄 클램프)를 3열로 깐다. 연도 묶음은 유지한다(묶음마다 그리드). 카드 폭 약 300px, 높이 약 330px. 54편 = 약 19줄, 약 6,500px.
- **모바일(< 640px):** 1열 큰 카드가 아니라 **가로 작은 카드**(커버 96×96 왼쪽 + 카테고리·날짜 · 제목 17px · 설명 2줄 · 읽기 시간). 행 약 120px, 54편 약 6,500px. 옛 그리드의 1열 큰 카드는 약 20,000px였다.
- **토글:** 검색창 옆에 "카드 / 목록" 버튼 2개(`data-js-only`). 고른 값을 `localStorage`에 둔다. 표시는 한 마크업에 `data-view="grid|list"` 속성으로 CSS만 바꾼다(DOM 2벌 아님). JS가 없으면 그리드다. 목록 모드는 지금 행(설명 1줄)이 아니라 **C의 강화 행**(설명 2줄, 커버 없음)이 자연스럽다. 지금 행 그대로 두어도 된다(사용자 결정).
- **비용:** 작다. `PostCard`·`PostCover`가 있다. 새 것은 가로 카드 CSS, 토글 `<script>`(약 30줄), `BlogList`의 그리드 배치.
- **영향:** HTML은 행마다 커버 마크업이 붙어 약 +25 KB(67 → 약 92 KB, 100 KB 안. 커버 색을 CSS 변수로 넘기면 더 작다). 검색 필터는 그대로(`data-post-row` 숨김). 스모크 2개의 정규식이 그대로 통과한다. 홈과 같은 카드라 사이트가 한 결이 된다.
- **약점:** 3열 카드는 설명 2줄에 약 42자가 들어간다. 54편 중 23편이 42자를 넘어 **잘린다**. 3줄 클램프(약 63자)면 7편만 잘린다. 카드마다 색이 있어 "같은 카테고리 23편"이 같은 색 벽이 된다(팔레트 분리로 완화. 5.4). 데스크톱 첫 화면에 카드 3편이 보인다(지금 약 5행).

### 5.2 B. 매거진형: 대표 1편 + 썸네일 행 (토글 없음)

- **데스크톱:** 맨 위에 **대표 글 1편**을 넓은 카드(커버 40% 왼쪽 + 제목 22px + 설명 전부 + 메타)로 둔다. 그 아래는 행마다 **작은 코드 커버**(128×72, 왼쪽) + 카테고리·날짜 + 제목 19px + 설명 2줄(약 100자. 54편 전부 보임) + 연재 배지·읽기 시간. 행 약 120px, 54편 약 6,700px(대표 카드 포함).
- **모바일:** 대표 카드는 세로형, 행은 커버 80×80 + 글자. A의 모바일과 거의 같다.
- **대표 글의 기준:** 데이터에 "대표" 칸이 없다. 최신 글 자동(가장 싸다), 또는 5단계에서 에디터 메타에 "대표 글" 표시를 더한 뒤 그것(그때까지는 최신 글).
- **비용:** 중간. 새 행 컴포넌트(커버 포함), 대표 카드, 모바일 CSS. 토글 없음.
- **영향:** HTML은 A와 같은 폭으로 는다. `data-post-row` 유지. 밀도와 훅을 한 화면에 가진다(toss·Medium·우아한 계열). 첫 화면에 대표 1편 + 행 1~2개.
- **약점:** 친구가 말한 "그리드"는 아니다. 대표 글을 "최신"으로 하면 늘 최신 글이 커서 의미가 약하다. 작은 커버는 큰 카테고리 글자가 작아져(라벨 약 14px) 정체성 효과가 줄어든다.

### 5.3 C. 목록 강화만 (커버 없음, 토글 없음)

- **데스크톱:** 행은 그대로이되 제목 19px/700, 설명 2줄(전부 보임), 카테고리를 글자(색 점 + 이름)로 보이고, 행 간격을 늘린다. 행 약 118px, 54편 약 6,400px. 우아한형제들·josh 방식.
- **모바일:** 설명 2줄을 숨기지 않는다. 행 약 130px, 54편 약 7,000px.
- **비용:** 가장 작다. CSS와 `PostRow` 마크업 조금.
- **영향:** HTML 거의 그대로(+3 KB). 검색·스모크 그대로.
- **약점:** 색 블록이 없다. 친구가 말한 "포인트"가 생길지 불확실하다. 참고 사이트가 글자만으로 되는 이유는 제목이 문장형이고 길기 때문인데, 이 블로그의 연재 글 21편은 제목이 짧다("22. Following Highlight").

### 5.4 어느 대안에나 함께 할 것 (Claude 판단, 구현 때 5절에 적는다)

1. **카테고리별 고유 팔레트.** `post-cover.ts`의 팔레트를 6개에서 9개로 늘리고, 카테고리 key → 팔레트를 표로 정한다(해시 대신). 지금은 9개 카테고리가 4색이다. 색이 카테고리를 구분해야 앵커가 된다. 홈 카드·OG 이미지(PR-C, 같은 함수)도 함께 바뀐다(U14 일관). 태그만 있는 글(카테고리 없음)은 지금처럼 해시다.
2. **설명을 2줄 이상 늘 보인다.** 모바일에서도 숨기지 않는다.
3. **날짜는 `MM.DD`에서 `YYYY.MM.DD`로 바꾸지 않는다.** 연도 묶음을 유지한다. 그리드에서는 묶음 머리가 전체 폭 행이다.
4. **제목에 `line-clamp`를 걸지 않는다**(U10의 "2줄 잘림"은 클램프가 만들었다). 설명만 클램프한다.

## 11. 추가 피드백: 필터 영역(탭 · 태그 칩 · 검색)이 지저분하다

친구의 2차 피드백(2026-11-10, 비교 HTML의 B 목업을 보고): "연재 3개 보기 →"와 목록 사이(카테고리 탭 · 태그 칩 · 검색칸)가 지저분하다. 카테고리 탭은 괜찮다.

1. 태그 칩이 정돈되지 않았다. 접을 수 있게 하면 어떨까.
2. 검색칸을 위의 빈 영역(제목 오른쪽)으로 옮기면 어떨까.

사용자: 친구의 제안을 잘 구현하는 방식 외에 더 나은·트렌디한 방식도 조사하라.

### 11.1 왜 지저분해 보이는가

| 원인 | 설명 |
|---|---|
| 폭이 제각각인 알약 12개가 3줄로 들쭉날쭉 감긴다 | 테두리가 있는 요소가 줄마다 다른 자리에서 끝난다. 눈이 윤곽을 따라가며 "모양"으로 읽는다. 글자 목록이면 생기지 않는 소음이다 |
| 칩마다 글 수가 붙는다 | 12개의 숫자가 글자 크기만 다르게 섞인다. 정렬 근거를 설명하지만 밀도를 높인다 |
| 검색칸이 칩 덩어리 옆에 떠 있다 | 칩은 왼쪽 아래로 흐르고 검색칸은 오른쪽 위에 혼자 있다. 두 요소의 기준선이 다르다. 제목 오른쪽은 비어 있다 |
| 탭(10) → 칩(12) → 검색 → 결과 수가 4층이다 | 컨트롤이 머리 영역의 절반(약 200px)을 차지한다. 2025~2026 블로그는 컨트롤을 1~2층으로 둔다 |

### 11.3 대안

공통: 카테고리 탭은 그대로. 검색 필터 동작(D2)과 `data-post-row`는 그대로. 연재 입구(D6: `/blog` 링크 · 태그 칩 · 글 상세 연재 상자 · 푸터)를 지킨다.

**F1. 검색은 제목 오른쪽, 태그는 한 줄 + "더 보기" (권장. 친구 제안 1·2를 다듬은 것)**

- 머리: 왼쪽 제목 · 설명 · "연재 3개 보기 →", 오른쪽 검색칸(아래 기준선 맞춤). 390px에서는 검색칸이 설명 아래 전체 폭.
- 탭 줄 그대로.
- 태그: 글 수 순 한 줄(928px에 약 6개. **연재 태그 3개(크래프톤-정글 · wesbos30 · pintos)가 모두 첫 줄에 든다** → D6 연재 입구 유지). 줄 끝에 "태그 6개 더 ▾" 버튼. 누르면 전부 펼치고 "접기 ▴". JS가 없으면 전부 보인다(지금과 같다).
- 결과 수 줄 그대로.
- 층수 4 → 3(머리 안으로 검색이 들어가 1층 줄고, 칩 3줄이 1줄). 머리 높이 약 90px 준다.
- 비용 작음: `BlogList` 머리 그리드, `TagChips`에 접기(`<script>` 약 15줄, `data-js-only`).

**F2. 검색은 제목 오른쪽, 태그는 알약 없는 글자 줄**

- 태그를 테두리 없는 글자 링크로 쓴다: `태그 · #크래프톤-정글 23 · #wesbos30 21 · …`. 보조색 14px, 1~2줄로 감긴다. 모두 보인다. JS 없음.
- 알약 윤곽이 사라져 소음이 준다. 글자 목록은 "모양"이 아니라 "글"로 읽힌다(overreacted.io 계열의 조용한 태그).
- 약점: 390px에서 3~4줄. 누르는 면적이 작다. 트렌디하다기보다 조용하다.

**F3. 검색은 제목 오른쪽, 태그는 "태그 12개 ▾" 버튼 뒤로**

- 결과 수 줄 오른쪽에 `<details>` 버튼 "태그 12개 ▾". 누르면 그 아래 칩 패널이 열린다. 기본은 닫힘. JS 없음(`<details>`).
- 가장 깨끗하다(컨트롤 2층: 탭 · 결과 수+태그 버튼). 목록이 약 130px 위로 올라온다.
