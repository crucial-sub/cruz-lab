## 3. 설계

### 3.1 고르기 규칙 (`src/admin/home/bulk-select.ts`, 순수 함수)

| 함수 | 하는 일 |
|---|---|
| `visibleSelection` | 고른 ID 중 지금 보이는 글만, 보이는 순서로 준다 |
| `toggleId` | 한 편 고르기·풀기. 받은 집합을 바꾸지 않는다 |
| `headerCheckState` | 머리 칸 모양: `none` · `some`(−) · `all`. 보이는 글만 센다 |
| `toggleAllVisible` | 보이는 글을 모두 골랐으면 모두 푼다. 아니면 보이는 글을 모두 고른다. 보이지 않는 고른 글은 남기지 않는다 |
| `selectionScopeKey` | 상태 탭 · 종류 · 검색어(앞뒤 공백 떼고 소문자) · 빈 초안 칩을 한 글자로. 이 값이 바뀌면 화면이 고른 것을 비운다. 정렬은 넣지 않는다 |
| `summarizeForDelete` | 확인 창 요약: 편 수, 발행 수, 숨김 수, 발행·숨김 제목(고른 순서, 5편까지), 나머지 수 |
| `canConfirmBulkDelete` | 지우기 단추를 켤지. 0편이면 끈다. 발행·숨김 글이 있으면 확인 칸이 체크돼야 켠다 |
| `runBulkDelete` | 일꾼 3개가 받은 순서로 한 편씩 가져가 지운다. 결과는 받은 순서로 준다: `deleted` · `failed`(이유) · `remaining` · `fatal` |

`runBulkDelete`의 오류 처리:

1. 404(이미 없음)는 지운 것으로 센다.
2. 401(세션 끝남)은 멈춘다. 새 글을 보내지 않는다. 이미 보낸 글은 끝까지 기다린다. 멈춘 글과 보내지 않은 글은 `remaining`이다.
3. 그 밖의 오류는 `failed`에 이유와 함께 넣고 다음 글로 간다.
4. 지운 직후 `onDeleted`(목록에서 빼기, 이 기기 보관 초안 지우기)를 부른다. 여기서 난 오류는 결과를 바꾸지 않는다.

이 파일은 런타임 import가 없다(`import type`만 있다). 그래서 스모크가 Node로 같은 함수를 불러 쓴다.

### 3.2 화면

| 폭 | 모양 |
|---|---|
| 768px 이상 | 표 맨 왼쪽 칸(머리 칸 포함). 표 위 막대: "N편 고름 (발행·숨김 M편) · 선택 해제 · 삭제". 아무것도 고르지 않으면 "고른 글 없음"이고 단추가 꺼진다. 고른 행은 옅은 초록 바탕이다 |
| 768px 미만 | 목록 위 줄 오른쪽에 "선택". 누르면 "보이는 글 모두 (N)" 칸과 "완료"가 생긴다. 행 전체가 고르는 칸이 된다(에디터 링크와 ⋯를 숨긴다). 화면 바닥에 "N편 고름 · 해제 · 삭제" 막대가 붙는다(iPhone 홈 막대 자리만큼 아래 여백). 목록 아래에 막대 높이만큼 여백을 둔다. "완료"는 선택 모드를 끄고 고른 것을 비운다 |

확인 창:

1. 제목 "글 N편 삭제". 본문 "초안·발행본·이전 판을 함께 지웁니다. 되돌릴 수 없습니다."
2. 발행·숨김 글이 섞이면 빨간 칸: "발행·숨김 글 M편이 섞여 있습니다. 발행 글 a편은 공개 주소가 404가 됩니다. 숨김 글 b편은 발행본도 함께 지웁니다." 그 아래 제목 5편과 "외 k편".
3. 그 아래 확인 칸 "발행·숨김 글 M편도 지웁니다". 체크해야 "N편 지우기"가 켜진다.
4. 지우는 동안 단추 글자는 "지우는 중… 끝난 수/전체"다. 취소·Esc는 꺼진다.
5. 확인 창은 연 때의 대상을 지닌다. 지우는 동안 목록이 줄어도 대상과 요약은 그대로다.

끝난 뒤:

1. 모두 지우면 확인 창을 닫고 알림 "N편을 지웠습니다."를 보인다. 휴대폰 선택 모드를 끈다.
2. 실패가 있으면 결과 창 "일부를 지우지 못했습니다"에 지운 수, 실패한 글의 제목과 이유를 보인다. 실패한 글만 고른 채로 남는다. 막대의 "삭제"를 다시 누르면 그 글만 다시 지운다(확인 창을 다시 거친다).
3. 401이면 확인 창을 닫고 로그인 화면으로 간다.
4. 알림 띠를 다시 읽는다(캐시 비우기 실패가 띠에 생길 수 있다).

### 3.3 서버 (바꾸지 않음)

지운 글마다 기존 한 편 삭제가 그대로 돈다: 글 문서 지우기(legacy·프로젝트 글은 묘비), 자산 `usedBy` 정리, `publishLog` delete 줄(`title`), CDN 퍼지, 백업 알림, 부수 결과 칸(`purge` · `backup` · `assetUsage`). 그래서 여러 편 삭제의 기록은 한 편 삭제 N번과 같다.

결정 4의 결과로 백업 알림이 지운 글 수만큼 간다. 백업 저장소 Action은 `concurrency: backup`(`cancel-in-progress: false`)이다. GitHub는 기다리는 실행을 하나만 남기고 나머지를 취소한다. 그래서 Actions 화면에 취소된 실행이 여러 개 보인다. 마지막 실행은 끝 상태를 백업한다.

### 5.4 화면 확인 (개발 서버 4341, Browser pane)

시험 초안은 서버 API로 만들었다(제목 "stage5-test 화면 확인 N", 발행 안 함).

데스크톱(1024×768):

1. 칸 두 개를 누르면 막대가 "2편 고름", 머리 칸이 "−", 고른 행이 초록 바탕이다.
2. 머리 칸: 일부 → 전부("5편 고름") → 없음("고른 글 없음").
3. 두 편을 고르고 "초안" 탭을 누르면 고른 것이 비워진다. "전체"로 돌아와도 비어 있다.
4. 초안 2편 삭제: 확인 창에 빨간 칸과 확인 칸이 없다. "2편 지우기" → 알림 "2편을 지웠습니다.", 목록에서 2편이 빠진다.
5. 발행 글이 섞인 확인 창: 시험 초안 1편과 실제 발행 글 1편을 골라 창만 열었다. 빨간 칸에 "발행·숨김 글 1편 … 공개 주소가 404가 됩니다."와 그 제목이 보인다. 확인 칸 전에는 단추가 꺼져 있고, 체크하면 켜진다. "취소"를 눌렀다. 발행 글은 그대로이고 고른 것은 남는다.
6. 일부 실패: 브라우저에서 시험 초안 1편의 DELETE만 가짜 500으로 바꾸고 2편을 지웠다. 결과 창에 "1편을 지웠습니다. 1편은 지우지 못했습니다."와 실패한 제목 · 이유가 보인다. 실패한 1편만 고른 채로 남는다. 가짜 실패를 풀고 "삭제"를 다시 누르면 그 1편이 지워진다.

휴대폰(375×812):

1. 평소 화면은 이전과 같고 목록 위에 "선택"이 있다.
2. "선택"을 누르면 행마다 칸, "보이는 글 모두 (4)", "완료", 바닥 막대가 생긴다. ⋯는 없다.
3. 행 제목을 누르면 고른다. 주소는 바뀌지 않는다(에디터가 열리지 않는다). 머리 칸이 "−", 바닥 막대 "2편 고름".
4. 가로 넘침 없음(`scrollWidth` 375). 끝까지 내리면 마지막 행 아래(696px)와 바닥 막대 위(763px) 사이가 비어 있다.

## 7. Claude 판단

사용자가 "고를 것이 있으면 AI 추천대로"라고 했다. 아래는 설계 요약에 없거나 그 뒤에 정한 것이다.

1. 머리 칸은 지금 보이는 글만 고른다(상태 탭 · 종류 · 검색 · 빈 초안 칩 뒤). 질문 전에 알렸다.
2. 탭 · 종류 · 검색어 · 빈 초안 칩이 바뀌면 고른 것을 비운다. 정렬은 비우지 않는다. 검색어의 앞뒤 공백과 대소문자는 목록 검색과 같게 무시한다. 질문 전에 알렸다(정렬 예외는 그 뒤 판단).
3. 이미 없는 글(404)은 지운 것으로 센다. 목적 상태(글이 없다)에 이미 있기 때문이다. 설계 요약에 적었다.
4. 401이면 멈추고 로그인 화면으로 간다. 보낸 글은 끝까지 기다린다. 남은 글은 지우지 않는다.
5. 지운 글의 이 기기 보관 초안도 지운다. 한 편 삭제와 같다.
6. 데스크톱 막대는 늘 보인다(그림 1과 같다). 0편이면 "선택 해제" · "삭제"가 꺼진다.
7. 휴대폰 선택 모드에서 ⋯를 숨긴다. 모두 지우면 선택 모드를 끈다. 실패가 있으면 켜 둔다(실패한 글이 고른 채 남아 있다).
8. 결과 창은 "닫기" 하나다. 다시 지우기는 막대의 "삭제"로 한다. 확인 창을 다시 거쳐 발행 글 확인 칸을 건너뛰지 않게 한다.
9. 숨김 글 문구를 발행 글과 나눴다. 숨김 글은 이미 공개 주소가 404라서 "404가 됩니다"가 맞지 않다. "발행본도 함께 지웁니다"로 썼다.
10. 진행 숫자는 끝난 수(성공 · 실패 모두)다.
11. Shift+클릭 범위 선택은 넣지 않았다.
12. ESLint 규칙 옵션을 하나 더했다(4절). 프로젝트 전체 설정이지만 이 규칙 하나의 옵션이다.
13. 스모크는 화면과 같은 `runBulkDelete`를 쓴다. 서버가 바뀌지 않았으므로 확인 대상은 "여러 번 부른 결과가 한 편 삭제 N번과 같은가"다.
14. 브랜치 이름은 `feat/admin-bulk-delete`다(앞 작업 `feat/image-rotate-flip`과 같은 꼴).
15. 빈 초안 칩 보기에서도 칸을 보인다. 여러 편 삭제는 "빈 초안 모두 지우기"의 보호 장치를 쓰지 않는다. 고른 글을 지우는 것이 사용자의 뜻이기 때문이다(6절 5).
16. 리뷰 지적 1 · 2 · 4 · 6을 고치고 3 · 5는 두었다(6절). 4의 수정(떠나기 가드)은 설계 요약에 없던 동작이다.
